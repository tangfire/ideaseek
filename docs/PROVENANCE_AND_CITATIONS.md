# 证据、引用与可追溯性规范

IdeaSeek 的报告必须让用户能从一个结论回到论文片段、数据版本、代码提交和实验运行。任何无法建立来源链的内容只能标记为推断、假设或建议。

## 证据链

```text
原始文件 hash
  → 解析片段/页码/图表/表格
  → PaperCard claim
  → 主题综合/研究地图
  → IdeaCard 主张
  → ExperimentSpec
  → code commit + dataset snapshot
  → RunResult + report conclusion
```

每条 claim 至少保存 `source_document_id`、文件 hash、页码或章节、片段偏移/图表标识、解析器版本和证据类型（原文事实/作者结论/平台推断）。PDF 解析不可靠时要标记置信状态，不能只保存一段无定位摘要。

## 报告语言

- **事实**：原文或日志直接支持，提供引用定位。
- **作者主张**：明确写成论文作者报告的结果，不当作平台复现结果。
- **平台推断**：说明推断依据和不确定性。
- **实验观察**：只引用当前 run 的指标和日志。
- **建议/假设**：写明尚未验证和否证条件。

## 引用输出

报告支持论文标题、作者、年份、DOI/arXiv/URL、项目仓库 URL/commit、数据集来源和代码许可证。生成 BibTeX/CSL JSON 时保留原始元数据和获取时间；同一论文的不同 PDF 版本用 canonical paper ID 合并，但保留文件 hash。报告尽量引用短片段和定位，不复制长篇全文。

## 结果来源

表格中的每个数值绑定 `run_id`、方法 ID、代码 commit、数据 snapshot、切分 manifest、指标实现版本和随机种子。原论文数值、本地 baseline 数值和 idea 数值必须分列，不能在汇总时混成一列。

## 失效与撤回

当输入文件、解析器、数据、代码、环境或指标版本改变时，受影响的 claim/result 标记为 stale，并指出需要重跑的下游节点。旧报告不删除；新报告显示基于哪个 snapshot 生成。发现错误证据时生成修订版本并保留审计记录。
