IDEASEEK
Research from evidence
Official user guide

从研究问题，走向可验证的发现。

IdeaSeek 帮你整理论文、数据和对比方法，提出有依据的研究 idea，在小规模实验中快速验证；你认可后，它再规划并执行全量 comparison 与 idea 实验，补齐论文证据，生成图表和 Overleaf 论文工程。

01 · First run

安装与初始化

IdeaSeek 面向联网的 Linux 科研服务器设计；Windows 用户优先通过 WSL2 或 SSH 使用。项目仍处于开发阶段，当前从源码检出安装。

bash 
git clone <IdeaSeek 私有仓库地址> ideaseek
cd ideaseek
pnpm install --frozen-lockfile
pnpm build
pnpm release-check

在一个新的研究方向文件夹里初始化项目。这个文件夹就是项目工作区：

bash 
mkdir my-research
cd my-research
node <IdeaSeek 仓库路径>/dist/cli.js init
node <IdeaSeek 仓库路径>/dist/cli.js setup
node <IdeaSeek 仓库路径>/dist/cli.js doctor

初始化会创建 papers/、datasets/、comparisons/、idea-seeds/、incoming/ 和平台管理的结果目录。它不会移动或覆盖你的原始文件。

05.5 · Material assessment

不知道还缺什么？让 IdeaSeek 先做材料缺口评估

你不需要一开始就知道该准备哪些论文、数据集或 comparison。IdeaSeek 会根据研究问题、已有论文、研究地图、数据画像、comparison 和目标场景，列出当前缺口以及它们对研究的影响。

缺口类型 例子 IdeaSeek 的处理
ANALYSIS 读取论文、数据和 comparison，评估研究材料缺口。 只写知识与缺口报告；不启动正式实验或锁定科学协议。
必须补 没有测试标签语义、主指标或 required baseline 阻止依赖它的正式实验，给出原因和下一步
建议补 缺少近期强基线、反例论文或第二个数据场景 说明它会影响哪些 claim，用户补充后提高覆盖
可选补 额外数据集、定性样例或扩展图表 记录为后续增强，不阻塞当前探索

每个建议都附来源、版本、许可证/访问条件、置信度、预计成本和放置目录。补充新材料后重新运行扫描，成功处理过的内容会复用。

02 · Project

一个研究方向，一个项目目录

通常在研究方向文件夹里启动 IdeaSeek。状态、论文索引、idea、实验、事件和 checkpoint 都属于这个项目。启动前可以用 ideaseek status 和 ideaseek next 查看当前状态与下一步。

不要把所有方向混进一个目录。你可以把多篇论文、多个数据集、对比代码和已有 idea 放在同一研究项目的对应输入区，IdeaSeek 会扫描并给出归类预览。
03 · Modes

Research、Analysis 与 Coding 协同模式

状态 / 入口 适合做什么 边界
RESEARCH 论文分析、协议、comparison、idea 和实验流程；自由文本由带上下文的 Supervisor 解答或转待审批决策。 遵守证据、数据、实验和审批门禁。
ANALYSIS 只读材料准备：运行 ideaseek prepare、ideaseek assessment 与只读材料问答，补齐论文/数据/comparison 缺口。 强制只读准备：拒绝写科研代码、锁协议、改 comparison 或启动实验。
CODING / /agent 复用 DSH 的通用 coding 会话（Alt+C 切换焦点，或 ideaseek agent / /agent）：理解项目、编辑代码、运行测试、修复工程问题。 不设目录写禁令，靠工具逐次审批、项目预算计费与回合末漂移侦测（ideaseek stale / /drift）保护科研完整性；保留底层档位显示（CODING · RESEARCH / CODING · ANALYSIS）。

交互界面底部与输入框顶栏显示当前状态；按 Shift+Tab 循环 Research / Analysis / Coding，按 Alt+C 随时正交开关 Coding 焦点（不改底层科研档位），或输入 /mode analysis、/mode research、/mode coding。

通用工程入口为 ideaseek agent "<任务>"：在任意目录启动真实的 DSH coding session（在 IdeaSeek 项目内自动记入审计与 max_model_cost 预算，并在回合末检查 papers/、datasets/、comparisons/*/upstream/ 漂移），--resume <sessionId> 续跑多步任务。工具审批默认安全拒绝：只有交互 TTY 会逐次询问 y/N（一次性授权），脚本环境用 --deny-tools 显式全拒。需要模型凭据（ideaseek models setup --test）。

bash 
ideaseek prepare --skip-model
ideaseek stale
ideaseek agent "run the test suite and fix the failing unit"
ideaseek agent --list
ideaseek agent "continue where you stopped" --resume <sessionId>
04 · Models

模型与凭据

首次启动自动检测 provider。你可以在终端里用隐藏输入配置 API key，立即测试连接，再选择默认模型；之后 /models 查看各角色使用的模型，必要时切换 route 或为高推理任务覆盖模型。Research 和 Agent 可使用不同路由。

密钥安全　API key 保存在 DSH credential store 或系统 secret manager，不写入项目配置、论文、日志或 Git。模型切换只影响新任务；运行中的 ResearchRun 保留启动时的模型快照。
bash 
ideaseek models
ideaseek models setup --api-key-env DEEPSEEK_API_KEY --prompt-key --test
ideaseek models test
ideaseek models use deep --confirm
ideaseek doctor

models setup 用隐藏输入收 key（自动化用 --api-key-stdin），写入 DSH credential store 的是环境变量名 与 user-config 引用；key 值只在内存里做一次连接测试，从不落盘。连接失败时零写入。 models test 随时复测，输出只有 presence 和状态，永不含 key。

05 · Inputs

放入论文、数据和对比方法

  • papers/：方向论文；解析后形成 PaperCard 和证据定位。
  • datasets/：已有数据或授权挂载；平台先画像，不会自动更改原始数据。
  • comparisons/：对比方法论文和代码；官方仓库与论文重实现会分别标记。
  • idea-seeds/：已有 idea、代码或实验结果；允许目录结构多样，由 intake 分析，不要求手工改成固定模板。
  • incoming/：暂时不确定归类的文件或压缩包。
bash 
ideaseek scan
ideaseek intake
ideaseek plan --question "你的研究问题"

scan 发现输入；intake 展示归类和歧义；确认前不移动、覆盖或执行用户文件。

06 · Explore

先计划，再做小规模探索

1

检查计划。运行 ideaseek plan --question "..."，先看材料、comparison、资源和阻塞。

2

确认协议和关键语义。例如数据字段、split、指标和 required comparison；无法安全推断的内容由你确认。

3

启动探索。运行 ideaseek start --question "..." 或交互输入研究需求；先用 smoke/quick/standard 小切片验证 idea。

4

看证据和反馈。检查 comparison、消融与失败分类；结果可能支持、否证或无法判断 idea，程序错误不能冒充科学结论。

05.5 · Analysis

先问 IdeaSeek：还缺什么材料？

进入 Analysis 模式后，IdeaSeek 会先把材料加工成 PaperCard、证据定位、主题综合、研究地图、机制库、DatasetCard 和 comparison 摘要，再列出必须补、建议补和可选补的论文、数据集、comparison、指标和场景，并说明来源、理由、成本和下一步。补齐材料后再切到 Research，让正式科研流程开始。

07 · Interactive

交互、命令与监控

真实 TTY 启动 Ink 交互界面。按 `/` 打开带说明的命令菜单，继续输入过滤；方向键选择，Tab 补全，Enter 执行，Esc 关闭。Shift+Tab 循环 Research / Analysis / Coding， Alt+C 随时正交开关 Coding 焦点（保留底层科研档位）。

输入 用途
/status 看项目、run、任务和阶段
/next 解释阻塞并给下一步
/prepare / /assessment 运行只读材料准备流或查看缺口报告
/drift 检查输入漂移与下游失效产物
/models 看模型 route/凭据状态
/pause / /resume 安全暂停和恢复
/quit 退出界面，不取消后台任务

自然语言可用于询问状态或提出建议。高影响动作必须先预览并确认；Agent 不得静默改指标、测试集或 comparison 清单。

08 · Results

结果、报告与 handoff

使用 ideaseek report 查看事实报告，检查 idea 状态、实验、失败项和证据来源。结果会区分原论文报告、本地 comparison、IdeaSeek 实验和未验证场景。

HANDOFF_READY 需要真实证据门槛通过；小规模正向结果不等于创新已证明，也不保证全量结果或论文录用。

补充实验：结果分析给出的缺口用消融与补充运行补齐，而不是改口径—— ideaseek idea ablation-plan <id> 从机制链生成消融计划， ideaseek idea ablate <id> --scale quick 按计划执行消融矩阵（每项绑定 idea 版本、spec 与代码哈希）； claim 侧用 ideaseek idea result-to-claim <id> 看全量结果实际支持什么， ideaseek idea claim-audit <id> 核对证据引用。

09 · Full Research

全量实验与论文交付

达到 HANDOFF_READY 后，你审阅 comparison 清单并确认数据、split、指标、预算和 GPU 时限。IdeaSeek 核验可信的官方/作者代码；缺少可用代码时按论文重实现并披露假设。随后所有 required comparisons 与 IdeaSeek 方法按锁定的公平协议运行。

结果分析会识别缺少的多种子、关键消融、comparison、数据或场景证据，并生成补充实验计划；在已授权预算和数据范围内继续运行、分析并更新主张与图表。需要新数据、权限、资源或改变科学协议时先向你说明并等待决定，不编造结果，也不无限试验直到出现正向结果。

批准后由平台内执行（探索管线永远没有 full 规模开关）：

bash 
ideaseek full fairness --idea <id>          # 逐方法对齐报告（可编辑）
ideaseek full fairness --idea <id> --confirm
ideaseek full plan --idea <id>              # 可审查的全量计划锁
ideaseek full approve --idea <id> --confirm  # 只批准，绝不自动开跑
ideaseek full run --idea <id> --confirm --detach   # 平台内全量执行
ideaseek attach --run <runId>               # 观察长任务

任何状态变化都会让旧批准失效（必须重新 fairness/plan/approve）； handoff 包保留为你自跑全量的替代路径（你的结果记为 USER_FULL_RESULT）。全量结果进入 ideaseek idea result-to-claim、claim audit 与独立 reviewer 后才进入图表与论文。

证据补齐后，IdeaSeek 复用 ARIS 的论文规划、绘图、写作与编译流程，交付带 BibTeX、图表源数据和 provenance 的 Overleaf 兼容工程。论文草稿由研究者审核，不承诺 venue 接收。

10 · Recovery

暂停、阻塞与恢复

外部模型/API、GitHub、数据源或 GPU 暂时不可用时，依赖任务应显示具体阻塞和恢复动作；其他不依赖该项的任务可以继续。补好凭据或环境后运行 ideaseek doctor、ideaseek next，再按提示 ideaseek continue。已提交 artifact 和成功任务不应重做。

11 · Troubleshooting

故障排除

症状 先跑 说明与恢复
命令报「no IdeaSeek project here」 ideaseek init 在研究方向的根目录初始化后再运行。
模型调用失败 / 无凭据 ideaseek models setup --test 隐藏输入配置并测连通；ideaseek models test 复测，输出永不含 key。
full plan/approve 报 stale ideaseek full plan --idea <id> 状态变了旧批准自动失效；重新 fairness → plan → approve 后再 run。
full run 拒绝：缺 entry / fairness 未确认 ideaseek baseline repair --method <id> --entry "..." 每个 required 方法必须有可运行入口；按提示补齐后重试。
run 显示 QUOTA_EXHAUSTED / NETWORK_BLOCKED ideaseek continue 补额度或恢复网络后继续；已成功的任务不会重做。
worker 断线 / 任务卡住 ideaseek status --detail 租约过期自动恢复；ideaseek watchdog 报告存活问题。
claim audit FAIL ideaseek idea claim-audit <id> 引用对不上论文或注册表——修证据或注册 comparison，handoff 会被挡住直到通过。
环境 / GPU / 依赖可疑 ideaseek doctor 版本、schema、权限、容量与凭据 presence 一次性体检（不打印 secret）。
备份与回滚 ideaseek backup / ideaseek restore <dir> 恢复前逐文件哈希校验；拒绝覆盖已有项目。

任何恢复动作都应在 开发进度 与事件流里留下可审计记录； 不确定时先 ideaseek next，它只解释阻塞与下一步，不启动高成本工作。

ideaseek backup快照工作流 DB + 配置 + 产物（sha256 清单）
ideaseek restore <backupDir>恢复备份到全新目录（哈希验证）
ideaseek export --run <id>导出运行产物、事件和任务（含哈希清单）
ideaseek archive --run <id>写只读归档包
ideaseek cleanup预览/删除可重建的平台文件（不动原始文件）
ideaseek logs <taskId>任务详情（脱敏错误和日志尾部）

TUI 快捷命令

在交互式 TUI 中输入 / 打开命令面板，支持模糊匹配和 Tab 补全。以下命令等价于对应的 CLI 形式。

概览

命令说明
/help显示帮助
/init在当前目录创建 IdeaSeek 项目
/status运行状态、任务、worker、最近事件
/next状态感知的下一步建议
/assessment材料就绪度和缺口报告
/prepare运行只读 Analysis 准备管线
/drift预览输入漂移和失效的下游产物

审批

命令说明
/pending等待你的审批（协议、代码修订、请求）
/approve [n]批准待处理项（或从 /pending 选择第 n 项）
/reject <reason>拒绝待处理提案并给出原因

研究

命令说明
/papers论文索引进度和解析失败
/comparisons对比方法、来源和阻塞
/ideasidea 列表（状态和版本）
/experiments已记录的实验规格和结果
/rounds检查 ideation 轮次
/ideate创建/继续 IdeationRound
/feedback记录用户反馈标签

会话

命令说明
/models [list|setup]模型路由/角色/凭据状态；配置 API key
/mode [research|analysis]显示/切换研究档位
/agent <指令>运行一次 DSH 编码会话
/open [target]选择项目或读取文档
/report写事实运行报告

控制

命令说明
/pause停止领取新任务
/resume恢复暂停的运行
/continue继续被阻塞的运行
/cancel取消运行（产物保留）
/quit退出 TUI（不取消后台运行）

?显示快捷键速查
