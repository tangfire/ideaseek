# IdeaSeek 可选领域插件

IdeaSeek 的通用底座负责论文知识、Agent 编排、comparison、代码修复、资源调度、checkpoint 和报告；具体项目的实验协议由论文、comparison 代码和用户数据共同综合出来。领域插件不是 IdeaSeek 的必需组成部分，也不是 idea 生成的前置条件。它们只在某个方向需要特殊格式解析、泄漏检查、指标或安全边界时增加，并且可以由用户、实验室或社区独立开发和安装。平台不要求用户预先手写科研规则：Protocol Synthesis Agent 负责提出协议，Evidence Checker 和 Dataset Analyst 负责检查，只有无法安全推断的科学语义才请求用户确认。

## 什么时候需要插件

优先使用通用能力。只有出现以下情况才建议写插件：

- 数据格式无法通过通用 parser 和用户提供的入口稳定读取；
- 某类泄漏规则必须由领域知识确定，通用检查器无法安全判断；
- 指标实现、仿真器或资源估算具有稳定的领域标准；
- 用户实验室已有可复用的任务模板，希望在多个项目中复用。

插件补充确定性能力，不替代论文学习、机制推理或 idea 生成。一个方向没有插件时，IdeaSeek 仍然可以用通用解析、Protocol Synthesis 和用户确认运行；插件缺失不能自动成为阻塞。

## 插件边界

插件可以声明 parser、dataset inspector、split validator、metric provider、experiment adapter 或 resource estimator。插件必须通过公开 schema 接口返回结构化结果，附来源、版本和错误，不得直接修改原始数据或绕过权限。插件不能注册第二套 Agent Loop；需要 Agent 推理时调用 IdeaSeek/DSH 提供的角色和工具。

用户可在项目中安装或启用插件，例如：

```bash
ideaseek plugin list
ideaseek plugin install <package-or-local-path>
ideaseek plugin enable <plugin-id>
ideaseek plugin doctor <plugin-id>
```

插件的代码、依赖、许可证、版本和 capability 都记录在项目 manifest；没有用户启用的插件不会参与运行。

## 适配器契约

每个适配器提供基础 schema、检查器和领域知识；每个项目运行时自动生成并版本化 `ExperimentalProtocolProposal`，至少包含：

- 任务类型和样本单位；
- dataset card 字段和数据质量检查；
- 训练/验证/测试或跨域/跨客户端切分规则；
- 预处理、标签、时间窗口、主体/组别边界和泄漏检查；
- 主指标、辅助指标、指标方向和统计汇总；
- comparison 角色和统一入口；
- ExperimentSpec、资源估算和最小 smoke test；
- 消融模板与机制判据；
- 结果标签、停止条件和可外推边界。

协议生成必须给每个字段附来源和置信度：论文证据、comparison 实现、数据探测、领域默认规则或 Agent 推断。适配器不能把所有科学选择都无条件猜出来；数据语义、标签、主体单位、关键切分规则和主指标存在实质歧义时，进入 `USER_INPUT_REQUIRED`，并展示候选解释、依据和影响。用户确认的是一个可审查的协议草案，而不是从零填写配置。

## 方向覆盖判断

| 方向 | 通用底座覆盖 | 必须专门定义的内容 | 首版可行性 |
|---|---|---|---|
| 多模态早期预测 | 论文分工、代码修复、多 GPU、idea 分支、实验闭环 | 模态同步、时间窗、缺失模态、预测提前量、事件级切分、时序泄漏、校准指标 | 通用能力可先运行；需要特殊规则时再装插件 |
| 短视频 | 论文阅读、代码复现、并行实验、视频预处理任务 | clip 采样、帧率/分辨率、时空增强、视频级 split、吞吐/显存、长视频缓存 | 通用能力可先运行；需要特殊规则时再装插件 |
| 图像分割 | baseline 发现、代码修复、消融、GPU 调度 | mask 格式、类别/实例/语义定义、重叠裁剪、Dice/IoU/边界指标、按主体切分 | 通用能力可先运行；需要特殊规则时再装插件 |
| 联邦学习模型异构 | 多 Agent、代码隔离、并行客户端实验 | 客户端划分、模型结构映射、通信轮次、聚合/蒸馏协议、客户端采样、通信成本 | 可先由通用协议生成器验证；必要时再加联邦仿真检查器 |
| 联邦学习域泛化 | 论文综合、comparison、idea 迭代 | 域定义、训练/未知域划分、跨域泄漏、客户端/域关系、泛化指标和统计方案 | 通用能力可先运行；需要特殊规则时再装插件 |

## 多 GPU 运行

以上方向都可以在单台 Linux 多 GPU 服务器上运行，但“多 GPU”不等于所有任务都可同时启动。调度器根据实时显存、CPU/内存、视频/图像缓存、客户端数量、通信模拟开销和项目配额决定并发。视频、多模态和联邦仿真可能同时消耗 GPU 与大量 CPU/内存；通用 ResourceEstimator 先做估算，只有特殊任务需要时才由插件补充。

联邦学习首版建议先做单机仿真：客户端是隔离进程/容器，使用确定性数据分片和可记录的通信/聚合事件；不要把“单机仿真结果”表述成真实跨设备部署结论。

## 协议自动综合流程

```text
论文实验表格/方法描述
  + comparison README/代码入口/评估脚本
  + 用户数据探测和 dataset card
  + 可选插件安全规则
  → ExperimentalProtocolProposal
  → Evidence/Leakage/Feasibility checks
  → 用户只确认有歧义的字段
  → Baseline smoke test
  → Protocol lock
```

协议锁定后，idea 和 comparison 只能在该版本协议下比较；协议变更生成新版本并让受影响实验失效。平台可以自动提出小规模切分、smoke test 和消融，但必须保留生成依据、随机种子、资源估算和停止条件。

## Idea 质量要求

适配器要把方向中的科学机制暴露给 Idea Agent。例如：

- 早期预测必须讨论提前量和信息泄漏，而不是只看最终分类准确率；
- 短视频必须区分空间、时间和跨帧机制，而不是简单拼接图像模型与时序模型；
- 分割必须说明边界、尺度或类别不平衡机制，而不是只换 backbone；
- 模型异构联邦必须解释如何处理表示/输出空间不一致，而不是只改聚合函数名称；
- 域泛化必须说明域不变性、域偏移或未知域风险，而不是随机混合客户端。

## 交付顺序

先选一个方向完成端到端适配器和人工 gold set，再复用通用底座扩展其他方向。建议优先图像分割或一个定义清晰的短视频任务；联邦方向和多模态早期预测的协议歧义、数据泄漏和资源估算更复杂，适合作为第二阶段。
