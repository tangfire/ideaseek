# 质量评估与验收

平台不能用“Agent 说有创新”作为验收标准。每次模型、prompt、解析器、索引或工具升级都要跑固定回归集。

## 文献质量

- PaperCard 字段准确率和完整率；
- 关键主张的证据支持率；
- 页码/章节定位准确率；
- 相关论文检索 Recall@k；
- 重复、冲突和解析失败识别率。

## Comparison 质量

- 官方代码、兼容修复和论文重实现的来源区分正确率；
- 依赖/入口诊断成功率；
- 统一协议下 baseline 运行成功率；
- 本地结果与论文设置的差异记录完整率；
- 算法语义改动被正确拦截率。

## Idea 与实验质量

- 最近邻工作召回率；
- IdeaCard 事实错误率和重复率；
- 机制链完整率：问题矛盾、介入机制、可观测预测和否证条件是否齐全；
- 表面组合率：被研究者判定为“无机制拼接”的候选比例（应持续下降）；
- 消融是否能区分候选机制而不只是删除代码组件；
- L0–L4 实验组合完成率，以及报告是否正确区分当前切片支持、稳定性、场景鲁棒性和外部验证；
- 跨种子/跨场景结果的一致性与未覆盖场景披露率；
- 研究者盲评的可检验性和价值；
- baseline/idea 数据、指标和预算对齐率；
- 基线复现误差、实验无效率、结果方差和选择偏差报告完整率；
- 代码、数据、环境和 run 是否可复现。

## 可靠性与体验

- checkpoint 故障恢复成功率；
- 已完成任务重复率和重复成本；
- 事件实时性、断线回放和后台 attach 成功率；
- GPU 资源超额分配次数（目标为零）；
- `next` 能否给出明确可执行建议；
- secret 出现在 prompt、日志、artifact 或容器中的次数（目标为零）。

## Gold set 和故障测试

维护人工标注论文/证据集、已知方法对、固定 dataset/实验项目和故障注入脚本。至少测试：模型请求前后崩溃、artifact 提交中断、租约失效、GPU OOM、SSH 断开、整机重启、输入变更、凭据失效和外部网络关闭。
