## 1. 问题定义

### 1.1 本产品的立项依据

IdeaSeek 的一次 run 可以跑数小时到数天。当前用户离开终端后，对这些长任务**没有任何可随时访问的视图**。这不是新发现的缺口，仓库里已经登记在册：

> `docs/PRODUCT_GAPS_AUDIT.md:94-96`（缺口⑩ 长任务的远程观察面）
> 通知只有 webhook 且仅在 run 终态触发；watchdog/monitor 是手动命令。用户离开终端后，对"还在跑的几天长任务"没有随时可查的轻量视图。要求：至少规划一条远程路径（IM 深集成、**只读状态页**或 `notify` 周期性心跳摘要），覆盖运行中状态而不仅是终态；通知内容保持脱敏摘要 + run/task ID。**待产品决策选型后进入 `PROGRESS.md`。**

本需求即为该"待产品决策选型"的答复：**选型 = 只读状态页，落地形态 = 部署在 Qoder Sites 的 Web 控制台**。

同一文档区还涉及三项相关能力——**其中⑨ 已收口（我最初误判为未实现，已按代码与 commit 证据改正）**，⑪⑫ 仍是真实缺口：

| 缺口 | 出处 | 内容 | 本产品的关系 |
| --- | --- | --- | --- |
| ⑨ 步骤级 Agent 过程可视化 | `PRODUCT_GAPS_AUDIT.md:84` | 登记于 2026-11-13，**已于 2026-11-14 收口**（`PROGRESS.md:445`，commit `f2a23eb`）：`tool_call` 与训练心跳实时进 RunEvent，`tests/step-visibility.test.ts` 门禁。**审计文档未同步，仍写成未完成** | 控制台**可做步骤级时间线**（F4.7），但覆盖范围有三条真实缺口，见 §3.4 |
| ⑪ 对外差异化定位 | `PRODUCT_GAPS_AUDIT.md:98` | 没有面向外部同类产品的定位叙事，"供 README/**落地页**引用"的落地页并不存在 | 落地页是控制台的第一屏，必须一并产出 |
| ⑫ 数据外发透明度 | `PRODUCT_GAPS_AUDIT.md:102` | 启动时确认允许外发，之后**没有任何外发账本**可查。已核实：`src/` 下无 egress 记账实现 | 控制台提供按 run 聚合的只读外发台账，**但须引擎先产出数据源**（M13 标 P2 的原因） |

### 1.2 一句话定位

> 让离开创载终端的研究者，用手机或任意浏览器随时回答："我的 run 现在卡在哪一步、为什么、花了多少、下一步要我确认什么"——而**不把自己的论文、数据和凭据交给云端**。

### 1.3 明确的非目标

以下不做，评审时请勿按这些方向提意见：

1. **不在云端运行科研引擎。** IdeaSeek 依赖 `node:sqlite` 原生绑定（`src/workflow/sqlite.ts:1`）、Python 子进程 worker、隔离容器和 TTY 交互，这些在托管环境不成立。控制台**只是投影与信箱**。
2. **不做云端执行入口。** 云端任何操作都不能直接触发本地计算、下载数据或花费预算（见 3.3 两阶段审批）。评审 Q2 已确认：需要"远程放行"时的正确做法是**本地预授权策略**（规则在本地定义、由本地引擎按 `autonomous` 语义判定执行），而**不是**给云端开一条能生效的写通道；该能力另立切片，不在本产品范围。
3. **不做本地状态的权威副本。** 云端库可随时整体删除并从本地重建；断云不影响研究。
4. **不做多租户 SaaS 计费、团队协作权限体系**。单所有者 + 受邀读者。
5. **不替代 CLI/TUI。** 首次项目创建、配置模型密钥、原始输入管理仍只在本地。

## 3. 核心设计约束（评审重点）

这四条是需求成立的前提。任何一条被推翻，架构需重做。

### 3.1 约束一：数据分级红线 —— 公开访问与私有科研数据的冲突

**冲突事实**：`docs/PRODUCT_GAPS_AUDIT.md:76` 明确"默认不把私有项目上传到平台共享评测集"；`docs/AGENTS.md` 数据约束规定"用户论文、数据、comparison upstream 和 GitHub 凭据不能进入 Git"。而本次要求是**公开访问 + 云端数据库**。

**解决方案：三级可见性 + allowlist 投影**，而不是"全都同步然后靠前端隐藏"。

| 数据级 | 内容 | 是否离开本机 |
| --- | --- | :-: |
| L0 绝密 | secret/API key、完整 prompt、模型隐藏推理、论文原文、数据集内容、原始日志、artifact 文件正文 | **否，永不** |
| L1 私有投影 | run 状态、阶段、任务计数、事件脱敏摘要、idea 假设文本、指标数值、成本 | 是（Owner 控制） |
| L2 公开投影 | 项目标题、研究问题、阶段进度、结论标签、聚合指标、idea 标题与机制摘要 | `visibility≠private` 时 |

可见性三态（Q1 评审结论，语义见下表）——**每一级只比上一级多一个动作，不做乘法**：

| `visibility` | 谁能读到 | 进入公开列表 | 触发动作 |
| --- | --- | :-: | --- |
| `private`（默认） | Owner + 受邀读者 | 否 | — |
| `link` | 持有分享链接/token 者 | 否 | 一次"发布"确认 |
| `listed` | 任意匿名访客 | 是 | `link` 之后再单独确认一次 |

拆成 `link` 与 `listed` 的理由：链接泄露只波及知情者，进列表等于投广告，两者的爆炸半径不是一个量级，因此必须是两个独立动作（FEATURE_LIST F5.9）。

规则：

- **默认一切私有**（`visibility=private`）。公开是逐项主动动作。
- 公开投影是私有投影的**再降级**，由独立 allowlist 生成，不是前端字段隐藏。数据库里公开角色读不到 L1 敏感列（行级 + 列级策略）。
- `idea.hypothesis`、`claim.text` 属于**未发表学术成果**：即使项目公开，默认不外泄全文，只给结构与状态；Owner 可逐项放开。
- L0 的过滤发生在**序列化之前**（本地侧），不在云端做净化。云端收到什么就存什么，因此本地投影器是唯一的安全边界，必须有独立测试（见 FEATURE_LIST F1.4）。

**已决议（Q1）**：接受"仅显式发布的项目对匿名可见"。首屏匿名访客只看得见合成演示项目，因此演示数据集（M7）是 P0 而非可选项。

### 3.2 约束二：单向投影，云端不是权威

```
本地 .research/workflow.sqlite（权威，唯一可写）
        │  ideaseek cloud push（Owner 授权，批量，幂等）
        ▼
Sites Function  /functions/v1/app/ingest  ← Bearer sync_token + schema 版本协商
        ▼
Sites Postgres  cloud_*（只读投影，可整体删除重建）
        ├──▶ /functions/v1/app/*        浏览器 SPA（REST 读：列表、详情、分页）
        └──▶ /functions/v1/app/live     浏览器 SPA（WebSocket 推：状态帧、批事件帧、心跳帧）
```

写入侧（`/functions/v1/app/ingest`）与读取侧（`/functions/v1/app/*` + `/functions/v1/app/live`）是两条独立通道，认证与限流各自定义；推送通道的契约、帧类型与运行时验收见 §5.4（选型 Q11，平台前提待 spike S6 验证）。

- 云端**不持有**任何只有云端知道的状态，除两类例外：审批意向（§3.3）和分享链接配置。
- 每次投影以 `sync_batch` 记录，携带本地 `schema_version`；未知版本或未知字段 → **拒绝整批并回执原因**，不做静默兼容（对齐仓库"损坏输入必须大声失败"的既有取向，见 commit `d0db9f3`）。
- 云端不做任何数值推断（如 ETA、成功率），只呈现本地已给出的判断与计数。需要推断的，交还给 Agent 在本地产出后投影。

### 3.3 约束三：审批是两阶段信箱，云端不落执行

现有审批模型有三种：`protocol | decision | repair`（`src/approval/pending.ts:15`）。

**不允许**云端一次 HTTP 调用就使审批生效，否则公网暴露的写入面等于远程执行入口。改为：

```
阶段一  本地引擎暂停在门槛 → 投影 approval_request（含选项与理由）
阶段二  Owner/Reviewer 在网页提交 approval_intent（选择 + 备注）
阶段三  云端只落 intent，标记 delivered_at，不通知、不驱动任何执行
阶段四  本地 `ideaseek cloud pull` 取回 intent → 仍在 TUI 二次确认 → 写入 Decision/RunEvent → 恢复
```

- 网页必须**明写**"此操作不会立即生效，需回本地确认"，防止用户误以为已在云上批准。
- 同一 `approval_request` 的多个 intent 不自动合并：本地展示全部并要 Owner 裁决。
- `autonomous` 自治模式下门槛本就自动通过，控制台不得阻塞或改写（`WORKFLOW_SPEC.md:86`）。

### 3.4 约束四：云端延迟来自同步节奏，而非引擎能力

已核实引擎侧能力（勿低估）：`harness_tool_call` 与 `experiment_progress` 已实时落 RunEvent（`src/runtime/usage-recorder.ts:116`、`src/experiment/progress-events.ts:51`），所以控制台**可以**做步骤级时间线。真正的限制是"多久推一次"。

延迟由两段组成，必须分开算：**引擎→云**取决于 push 节奏（Q9 已决：关键节点立即推，平稳期 5 min 心跳），**云→浏览器**取决于取数方式（已决：WebSocket 服务端推，替代前端轮询）。

| 视图 | 延迟目标 | 引擎→云 | 云→浏览器 | 界面措辞 |
| --- | --- | --- | --- | --- |
| 阶段与门槛变更 | ≤ 10 s | 事件驱动立即推 | WS 推送 | 可写"即时同步" |
| 任务失败 / run 终态 | ≤ 10 s | 事件驱动立即推 | WS 推送 | — |
| 心跳/存活 | ≤ 5 min | 兜底周期心跳 | WS 推送 | "最后同步于 x 分钟前" |
| 步骤级事件流 | ≤ 5 min | 随批 push | WS 推送（无新事件不投影） | 时间线，标注批更新 |
| 终态结果 | 批次完成即有 | 同上 | WS 推送 | — |

浏览器侧不做倒计时轮询：页面先 REST 拉全量、再建 WS 订增量；断开后指数退避重连，并在重连成功后补一次 REST 全量（防漏帧）。频道路径、帧类型与降级策略见 §5.4。

**步骤级事件的三条真实覆盖缺口**（`PROGRESS.md:445`/`450` 记录在案），界面必须如实表达：

1. **消融（ablation）路径未接 `onProgress`** → 消融实验只有阶段态，无训练心跳。视图须标"此实验无进度事件"，不能留白让人以为卡死。
2. **无 run 的独立实验**进度只落 `progress-<specId>.json`（`run_event` 有 FK 约束） → 这类实验在控制台不可见，需明确指引回 CLI。
3. **`ideaseek agent` coding 回合**的步骤仅 TUI 回合内展示，未持久化进 RunEvent → 控制台不得显示 agent 会话过程。

界面**禁止**出现"实时"字样：WS 消灭的是浏览器轮询延迟，消灭不了引擎侧的 push 周期——正在跑的模型调用内部过程在落入 RunEvent 之前对云端不可见，写"实时"即构成 R3。允许"即时同步/刚同步"，禁止"实时直播"。这是措辞级需求，列入验收（F4.4）。

## 5. 非功能需求

| ID | 类别 | 要求 | 验收方式 |
| --- | --- | --- | --- |
| NFR-01 | 安全 | L0 数据在本地序列化阶段即被剔除；投影器有 secret 模式扫描（key 形状、`sk-`、PEM、token）并单测 | 构造含 20 种 secret 样本的 fixture，断言 0 泄漏 |
| NFR-02 | 安全 | `sync_token` 仅存哈希，可单项吊销，绑定 Owner + 项目范围 | 吊销后 push 返回 401 |
| NFR-03 | 安全 | 事件摘要长度上限（建议 ≤ 400 字符），沿用 `DATA_CONTRACTS.md:73`"公开摘要"约定 | 超长在本地截断并标记 |
| NFR-04 | 隐私 | `visibility` 变更即时生效；公开→私有后旧分享深链立刻失效 | 集成测试 |
| NFR-05 | 隐私 | Owner 可一键删除项目全部云端投影（被遗忘路径） | 删除后所有读接口 404 |
| NFR-06 | 幂等 | 同一 `external_batch_id` 重复 push 不产生重复行；`run_event` 按 `(run_id, seq)` 唯一 | 重放测试 |
| NFR-07 | 兼容 | 投影 schema 带版本号；Function 拒绝未知主版本并回执，不静默丢字段 | 版本协商测试 |
| NFR-08 | 可靠 | 云端不可达不影响本地 run；push 失败本地排队重试，不丢投影 | 断网演练 |
| NFR-09 | 性能 | 首屏（项目总览）P95 < 2s；单 run 事件流分页 200 条/页 | Lighthouse + 手工 |
| NFR-10 | 可观测 | Function 记录请求量、拒绝原因分布（不含正文），可在控制台自查同步健康度 | 日志抽样 |
| NFR-11 | 可访问性 | 关键状态不以颜色为唯一载体（阶段/结论必须带文字），对比度 AA | 手工核查 |
| NFR-12 | 一致性 | 所有状态标签直接取引擎枚举原文，禁止前端翻译或臆造中间态 | 代码评审 |
| NFR-13 | 诚实性 | 界面不得把 `smoke`/`quick` 切片结果表述为已验证结论；不得把 synthetic 指标当结果（对齐 `RESEARCH_INTEGRITY` 红线） | 文案评审 |
| NFR-14 | 安全 | 投影器的**唯一数据源是 SQLite 与 artifact 记录**，不得遍历 `papers/`、`datasets/`、`comparisons/` 或项目根目录（`.env` 明文密钥风险见 R9）；任何文件类字段只投影已入库的 hash 与相对引用 | 代码评审 + 断言"投影过程不产生 readdir" |
| NFR-15 | 安全 | push 前密钥形状扫描命中即**整批拒绝并本地报错**（fail-closed），不允许"警告后继续上传" | 注入真 key 形状 fixture，断言零出网 |
| NFR-16 | 实时性 | 浏览端状态变更推送 P95 < 1 s、P99 < 3 s；`/functions/v1/app/live` 断开后自动重连并在重连成功后补一次全量 REST；单连接只能订阅自己按可见性规则本可读取的行 | §5.4.4 推送运行时验收矩阵（含鉴权矩阵） |

NFR-13 是本产品最容易犯错的地方：一个好看的公开网页，天然会把"小规模切片上的初步信号"渲染成"研究成果"。**这是需求，不是样式问题。**

### 5.4 推送通道 `WS /functions/v1/app/live`

Q9 决定引擎→云的节奏，本节决定云→浏览器的通道。选型见 Q11，平台前提待 S6 验证（`PLAN.md §3`）。

#### 5.4.1 频道与鉴权

| 项 | 契约 |
| --- | --- |
| 端点 | `wss://<site>.qoder.site/functions/v1/app/live`，站点同源，不引入第二个域名 |
| 订阅粒度 | 按**项目**订阅：`?project=<slug>`；`run` 级细粒度不做（run 数多，频道爆炸且收益仅是少几帧） |
| 匿名（`listed`） | 握手即放行，服务端只推 L2 列——**同一份脱敏投影，不是靠前端过滤** |
| `link` 持链者 | 握手携带 `?token=<share_token>`，token 无效或已撤销 → 关闭码 4403 |
| 受邀读者 / Owner | 站点会话 Cookie（同源自动带上），无 Cookie → 按匿名降级 |
| 授权时机 | **握手时一次性判定，不做运行时热改**：连接存活期间的可见性变更不追溯已有连接，由客户端在收到 `revoked` 帧或重连时重新判定（见 5.4.3） |

**同源是硬约束，不是实现细节。** 项目状态虽已脱敏，但仍属未发表科研数据，且它是可被用作定向探测的持续信号；WS 不像 REST 受 CORS 预检天然约束，Origin 必须在握手时白名单校验，只放行本站点来源。

#### 5.4.2 帧类型

三种帧，全部带 `ts`（服务端时间）与 `seq`（连接内单调递增）。客户端以 `seq` 去重与检测空洞。

| `type` | 载荷 | 触发条件 | 频率上限 |
| --- | --- | --- | --- |
| `state` | 项目/run 状态摘要：stage、阶段计数、run 状态、待审批计数 | ingest 写入命中立即推条件（阶段变更 / 门槛到达 / 任务失败 / run 终态） | 1/s/项目，超出合并 |
| `events` | 批事件帧：`run_event` 增量，≤ 50 条或 ≤ 8 KB，**只含脱敏摘要不含正文**（NFR-03） | 随 push 批次 | 1 帧/批 |
| `ping` | 存活帧：`{last_ack_seq, last_sync_age_s}` | 服务端 30 s 空闲 | 1/30s |

`last_ack_seq` 让"引擎已经推到云端但还没显示"可判定：客户端据此渲染"已同步至 seq N"，而不是给一个无法证伪的时间戳。这是"安静"与"已死"在界面上唯一可区分的手段。

**帧生成走物化变更流，不在 WS 层重新查询。** ingest 事务内把变更写入 `live_outbox`，广播 worker 消费——避免每个连接各查一次投影表，也避免 REST 和 WS 两条路径写出两套视图（这是本项目最容易长出重复逻辑的地方）。

#### 5.4.3 生命周期与降级

| 场景 | 行为 |
| --- | --- |
| 打开页面 | 先 REST 拉全量（首屏，NFR-09），再建连订增量 |
| 断开 | 指数退避 1→2→4→8→16→30 s 封顶；抖动 ±20% 防重连风暴 |
| 重连成功 | **必须先补一次 REST**，再处理增量帧——漏帧会让计数永久错误，而计数错误正是本产品最不该犯的错 |
| 后台标签页 | `document.visibilityState=hidden` 主动关闭连接，回前台重连补帧（省电与连接配额） |
| 可见性撤销 | Owner 把项目转 `private` 后，服务端在 ≤ 5 s 内推 `revoked` 帧并关闭相关连接；页面立刻切占位态并丢弃缓存——与 NFR-04 的 REST 语义等价 |
| 服务端重启 | 连接全断，客户端退避重连 + 补 REST，无需额外机制 |
| S6 不通 | 降级短轮询 + 变更指纹（`PLAN.md §3` S6），帧语义不变，NFR-16 P95 放宽为 ≤ 15 s |

#### 5.4.4 推送运行时验收

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| WS-01 | 单次 push 含阶段变更 | 浏览器 < 1 s 渲染新阶段（**由注入事件的单测计时，不用人眼估**） |
| WS-02 | 平稳期连开 3 个页面 10 min | 0 个数据帧，仅 `ping`；托管库读次数 = 首屏 REST 次数，不随连接数增长 |
| WS-03 | 网络中断 45 s 后恢复 | 退避重连；重连后第一个动作是 REST 全量；计数与权威一致 |
| WS-04 | 空洞检测 | 人工丢弃一帧，客户端检测到 `seq` 跳号并触发一次 REST 补齐 |
| WS-05 | 匿名连接订阅 `private` 项目 | 关闭码 4403，且服务端日志记录拒绝原因（NFR-10） |
| WS-06 | `link` token 撤销 | 已建立的连接 ≤ 5 s 内收到 `revoked` 并断开；新握手被拒 |
| WS-07 | 越权订阅 | 同一 Owner 用项目 A 的连接请求项目 B（非其所有）→ 拒绝，不复用会话宽松判定 |
| WS-08 | Origin 不在白名单 | 握手失败，返回 403 |
| WS-09 | `events` 帧 51 条 / 9 KB 边界 | 截断 + `has_more` 标记，客户端从 REST 补齐 |
| WS-10 | `archived` 项目（Q7） | 不出现在列表、不可建连；`?follow=1` 显式打开时以"已归档"横幅渲染且不推帧 |
| WS-11 | 与 REST 同 `seq` 重复 | 客户端幂等，画面无重复条目 |
| WS-12 | 连续 30 min 静默后首次真实变更 | 该变更 < 1 s 推达，不得因"很久没推"被节流丢弃 |
| WS-13 | 密钥形状出现在事件摘要 | 本地投影器在序列化前拦截整批（NFR-15），断言 WS 层零命中 |

WS-05/06/07/08 是本节唯一**新增攻击面**的四条，优先级等同 P0 安全项；WS-01/02 是 Q11 立项目标的直接验证。

### 8.2 新增约束（评审中提出，已用代码核实并当场结案）

**`cloud push` 与运行中 run 的并发语义**——负责人要求这是"M2 开工前必须确认的第一件事，不是可以边写边想的东西"。已查实，现结案：

| 事实 | 证据 | 结论 |
| --- | --- | --- |
| 项目锁**互斥，且对存活的外部 pid 直接抛错** | `src/runtime/project-lock.ts:76-83` → `RUN_BLOCKED` | 若 `cloud push` 取项目锁，它**恰好在唯一需要它的时刻（run 正在跑）必然失败**。故 **push 不得获取项目锁** |
| 工作流库运行于 **WAL** 模式 | `src/workflow/sqlite.ts:581` `PRAGMA journal_mode=WAL` | WAL 支持单写多读并发，只读投影可与 supervisor 同时持有库 |
| 已存在**只读打开**路径 | `sqlite.ts:530` `new DatabaseSync(path, { readOnly: true })`；`:500-501` 注释已明确 "`VACUUM INTO` reads through the WAL" | 投影器复用既有只读打开方式，不改任何写路径 |

**据此定的实现契约**（F1.15，P0）：全部读取在**单个只读事务**内完成——WAL 下一个 read transaction 即一致性快照，避免跨表读到撕裂状态（例如取到 `run_event seq=100` 却取到尚未更新的 `stage_progress`）。

**M2 必须实测的失败模式**（诚实标注为**未验证**）：WAL 库在 `-wal` 需要恢复时，只读连接可能报 `SQLITE_CANTOPEN`/`SQLITE_READONLY_*` 而打不开（如上次进程崩溃留下热日志）。按仓库"损坏输入必须大声失败"的既有取向，此时应**响亮报错并指路 `ideaseek doctor`**，禁止退化为"读不到 = 没有新进度"的静默空投影。此路径须有回归测试，列为 M2 出口门禁。
