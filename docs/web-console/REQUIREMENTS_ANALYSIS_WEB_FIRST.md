# IdeaSeek Web-First 需求分析

> 从"CLI 中心 + 云端只读投影"转向"Web 控制台中心 + 本地执行节点"

---

## 1. 现状分析

### 1.1 当前架构

```
┌─────────────────────────────────────────────────────────────┐
│  本地机器 (CLI 中心)                                          │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │ ideaseek CLI │──│  SQLite DB   │──│  Artifact Store  │  │
│  │ (唯一入口)    │  │ (项目状态)    │  │ (论文/代码/结果)  │  │
│  └──────────────┘  └──────────────┘  └──────────────────┘  │
│         │                                                   │
│         │ cloud push (单向同步)                               │
│         ▼                                                   │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  Qoder Sites (只读投影)                               │    │
│  │  - 项目列表                                           │    │
│  │  - 运行状态                                           │    │
│  │  - 事件时间线                                         │    │
│  │  - 审批/成本/外发 (仅展示)                            │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 当前限制

| 限制 | 说明 |
|------|------|
| **项目创建** | 只能在本地 CLI 执行 `ideaseek init` |
| **运行控制** | `start`/`pause`/`continue` 只能本地执行 |
| **输入管理** | 论文/数据/代码必须本地放入目录 |
| **Git 操作** | commit/push/branch 只能本地 CLI |
| **配置管理** | 模型/凭据/协议只能本地配置 |
| **云端角色** | 纯只读，无法触发任何操作 |

### 1.3 用户痛点

1. **必须开终端**：每次操作都要切换到 CLI，打断科研工作流
2. **远程无法操作**：离开本地机器后只能看不能动
3. **状态不直观**：Git 仓库状态、文件变更需要命令行查看
4. **协作困难**：无法通过链接分享项目并让他人参与操作

## 2. 目标架构

### 2.1 新架构

```
┌─────────────────────────────────────────────────────────────┐
│  Qoder Sites (控制平面)                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │  Web 控制台   │──│  Cloud DB    │──│  Function API    │  │
│  │ (操作入口)    │  │ (项目状态)    │  │ (命令下发)        │  │
│  └──────────────┘  └──────────────┘  └────────┬─────────┘  │
│                                                │            │
│                                                │ WebSocket  │
│                                                ▼            │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  本地执行节点 (Local Agent)                           │    │
│  │  ┌──────────────┐  ┌──────────────┐                 │    │
│  │  │ 命令执行器    │──│  SQLite DB   │                 │    │
│  │  │ (接收并执行)  │  │ (同步状态)    │                 │    │
│  │  └──────────────┘  └──────────────┘                 │    │
│  │  ┌──────────────┐  ┌──────────────┐                 │    │
│  │  │ Git 客户端    │──│ Artifact Store│                 │    │
│  │  │ (仓库操作)    │  │ (文件管理)    │                 │    │
│  │  └──────────────┘  └──────────────┘                 │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 核心变化

| 维度 | 现状 | 目标 |
|------|------|------|
| **操作入口** | CLI 唯一 | Web 优先，CLI 保留 |
| **项目创建** | `ideaseek init` | Web 创建 + 本地同步 |
| **运行控制** | 本地命令 | Web 触发 + 本地执行 |
| **Git 操作** | 命令行 | Web 可视化 + 一键操作 |
| **文件管理** | 本地目录 | Web 上传/浏览/编辑 |
| **云端角色** | 只读投影 | 控制平面 + 状态同步 |

## 3. 功能需求

### 3.1 项目管理 (P0)

#### F1: 项目创建

**用户故事**：用户在 Web 控制台点击"新建项目"，填写项目名称和研究问题，系统创建项目并同步到本地。

**功能点**：
- [ ] F1.1 新建项目表单（名称、研究问题、策略选择）
- [ ] F1.2 项目模板选择（空项目 / 演示项目 / 从 Git 仓库导入）
- [ ] F1.3 创建后自动生成项目目录结构
- [ ] F1.4 项目列表显示所有项目（本地 + 云端）

**技术挑战**：
- Web 创建项目后，如何同步到本地执行节点？
- 需要 Local Agent 监听云端命令并执行文件系统操作

#### F2: 项目列表

**用户故事**：用户在控制台首页看到所有项目卡片，显示项目状态、最后同步时间、当前阶段。

**功能点**：
- [ ] F2.1 项目卡片视图（网格/列表切换）
- [ ] F2.2 项目状态筛选（运行中/暂停/完成/错误）
- [ ] F2.3 项目搜索（按名称/研究问题）
- [ ] F2.4 项目排序（最近同步/创建时间/名称）
- [ ] F2.5 批量操作（删除/归档/导出）

## 4. 技术架构设计

### 4.1 Local Agent 设计

Local Agent 是运行在用户机器上的守护进程，负责：
- 监听云端命令（WebSocket）
- 执行 CLI 命令（`ideaseek start`/`scan`/`git commit` 等）
- 同步状态到云端
- 管理本地文件系统

```typescript
// Local Agent 伪代码
class LocalAgent {
  private ws: WebSocket;  // 连接云端
  private cli: CLIExecutor;  // 执行 ideaseek 命令
  private git: GitClient;  // 执行 git 命令
  private fs: FileManager;  // 管理文件

  async onCommand(cmd: CloudCommand) {
    switch (cmd.type) {
      case 'start_run':
        await this.cli.run(['start', '--question', cmd.question]);
        break;
      case 'git_commit':
        await this.git.commit(cmd.files, cmd.message);
        break;
      case 'upload_file':
        await this.fs.save(cmd.path, cmd.content);
        break;
    }
    await this.syncStatus();  // 同步状态到云端
  }
}
```

### 4.2 云端 Function API 扩展

当前 Function 只有读接口，需要增加写接口：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/commands/run` | POST | 触发运行 |
| `/commands/pause` | POST | 暂停运行 |
| `/commands/git/commit` | POST | 提交变更 |
| `/commands/git/push` | POST | 推送到远程 |
| `/files/upload` | POST | 上传文件 |
| `/files/delete` | DELETE | 删除文件 |
| `/projects` | POST | 创建项目 |

### 4.3 数据同步策略

```
┌────────────────────────────────────────────────────────────┐
│  同步方向                                                    │
│                                                            │
│  本地 → 云端 (状态同步)                                      │
│  - 项目状态                                                  │
│  - 运行事件                                                  │
│  - Git 提交历史                                              │
│  - 文件哈希清单                                              │
│                                                            │
│  云端 → 本地 (命令下发)                                      │
│  - 运行命令                                                  │
│  - Git 操作命令                                              │
│  - 文件上传                                                  │
│  - 配置更新                                                  │
└────────────────────────────────────────────────────────────┘
```

## 6. 风险与挑战

### 6.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| **Local Agent 稳定性** | 高 | 守护进程 + 自动重启 + 心跳检测 |
| **文件同步冲突** | 中 | 版本控制 + 冲突检测 + 用户确认 |
| **Git 操作安全性** | 高 | 沙箱执行 + 凭据加密 + 操作审计 |
| **WebSocket 断连** | 中 | 重连机制 + 命令队列 + 离线缓冲 |
| **大文件传输** | 中 | 分片上传 + 断点续传 + 进度显示 |

### 6.2 产品风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| **架构复杂度增加** | 高 | 分阶段实施，每阶段可独立交付 |
| **用户学习成本** | 中 | 保持 CLI 兼容，渐进式迁移 |
| **安全性担忧** | 高 | 本地执行，云端不接触原始数据 |
