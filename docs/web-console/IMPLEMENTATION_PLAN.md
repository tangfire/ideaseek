# IdeaSeek Web-First 实施计划

> 基于 [REQUIREMENTS_ANALYSIS_WEB_FIRST.md](./REQUIREMENTS_ANALYSIS_WEB_FIRST.md) 的具体实施步骤

## Phase 1: Local Agent 基础框架

### 目标
建立本地守护进程，实现云端命令监听与 CLI 命令执行能力。

### 步骤

#### 1.1 Local Agent 项目初始化
- [ ] 创建 `local-agent/` 目录
- [ ] 初始化 Node.js 项目（TypeScript）
- [ ] 配置 `tsconfig.json`、`package.json`
- [ ] 添加依赖：`ws`（WebSocket）、`child_process`（CLI 执行）、`fs-extra`（文件操作）

#### 1.2 WebSocket 客户端
- [ ] 实现 WebSocket 连接管理（连接/重连/心跳）
- [ ] 实现命令接收与解析
- [ ] 实现命令执行结果回传
- [ ] 添加连接状态指示（连接中/已连接/断连）

#### 1.3 CLI 命令执行器
- [ ] 实现 `execCommand(cmd: string, args: string[])` 方法
- [ ] 实现命令超时控制（默认 30 分钟）
- [ ] 实现命令输出捕获（stdout/stderr）
- [ ] 实现命令取消机制

#### 1.4 命令路由
- [ ] 定义命令类型枚举（`START_RUN`/`PAUSE_RUN`/`GIT_COMMIT` 等）
- [ ] 实现命令分发器（根据类型路由到对应处理器）
- [ ] 添加命令队列（离线时缓存，重连后执行）

#### 1.5 状态同步
- [ ] 实现本地 SQLite 状态读取
- [ ] 实现状态变更事件监听
- [ ] 实现状态推送（本地 → 云端）
- [ ] 添加同步游标（只同步增量）

#### 1.6 守护进程管理
- [ ] 实现进程保活（崩溃自动重启）
- [ ] 实现日志记录（文件日志 + 控制台）
- [ ] 实现配置管理（读取 `.ideaseek/agent.yaml`）
- [ ] 添加启动脚本（`ideaseek agent start`）

## Phase 2: 云端 API 扩展

### 目标
扩展 Qoder Sites Function，增加写操作接口。

### 步骤

#### 2.1 命令接口
- [ ] 新增 `POST /commands/run` — 触发运行
- [ ] 新增 `POST /commands/pause` — 暂停运行
- [ ] 新增 `POST /commands/continue` — 继续运行
- [ ] 新增 `POST /commands/cancel` — 取消运行
- [ ] 添加命令鉴权（验证 sync_token）

#### 2.2 Git 操作接口
- [ ] 新增 `POST /commands/git/commit` — 提交变更
- [ ] 新增 `POST /commands/git/push` — 推送到远程
- [ ] 新增 `POST /commands/git/pull` — 拉取更新
- [ ] 新增 `POST /commands/git/branch` — 创建分支
- [ ] 添加 Git 操作鉴权（验证项目 Owner）

#### 2.3 文件操作接口
- [ ] 新增 `POST /files/upload` — 上传文件（支持分片）
- [ ] 新增 `DELETE /files/:path` — 删除文件
- [ ] 新增 `GET /files/:path` — 下载文件
- [ ] 新增 `GET /files/list` — 列出目录
- [ ] 添加文件大小限制（单文件 500MB）

#### 2.4 项目 CRUD 接口
- [ ] 新增 `POST /projects` — 创建项目
- [ ] 新增 `GET /projects` — 项目列表
- [ ] 新增 `GET /projects/:id` — 项目详情
- [ ] 新增 `DELETE /projects/:id` — 删除项目
- [ ] 新增 `PATCH /projects/:id` — 更新项目配置

#### 2.5 数据库 Schema 扩展
- [ ] 新增 `cloud_commands` 表（命令队列）
- [ ] 新增 `cloud_files` 表（文件元数据）
- [ ] 新增 `cloud_git_ops` 表（Git 操作记录）
- [ ] 添加索引优化查询性能

## 依赖关系

```
Phase 1 (Local Agent)
    ↓
Phase 2 (云端 API) ← 依赖 Phase 1 的命令格式
    ↓
Phase 3 (前端项目管理) ← 依赖 Phase 2 的项目 API
    ↓
Phase 4 (运行控制) ← 依赖 Phase 1 + Phase 2
    ↓
Phase 5 (文件管理) ← 依赖 Phase 1 + Phase 2
    ↓
Phase 6 (Git 可视化) ← 依赖 Phase 1 + Phase 2
    ↓
Phase 7 (高级 Git) ← 依赖 Phase 6
    ↓
Phase 8 (配置管理) ← 依赖 Phase 3
    ↓
Phase 9 (协作分享) ← 依赖 Phase 3 + Phase 8
    ↓
Phase 10 (安全可靠) ← 贯穿所有 Phase
```
