# IdeaSeek 专业产品需求清单

这份清单补充架构文档之外的产品级要求。它关注用户能否理解、控制、恢复和复核一个长时间运行的科研工作流。

## P0：首次使用与可理解性

- `ideaseek start` 在执行高成本任务前展示输入摘要、运行模式、预计论文任务数、模型费用范围、GPU 时间范围、磁盘需求和需要用户确认的科学问题。
- `ideaseek plan --question "..."` 只生成计划、候选 comparison、协议草案和资源估算，不启动 Agent 或实验。
- `ideaseek next` 对每个阻塞说明：原因、影响、已完成内容、推荐选项、可复制命令和是否会产生费用。
- `ideaseek explain <task|decision|artifact>` 能说明一个结果由哪些输入、版本、Agent、工具和规则产生。
- 首次运行提供小样本 demo/fixture，用户不用准备真实论文和数据也能检查安装是否正确。
- 破坏性或高成本操作显示确认摘要；普通低风险解析和重试不反复打断用户。

## P0：运行控制与可观测性

- 前台、后台、attach、watch、事件回放、plain、JSON 和交互模式行为一致。
- `status` 提供阶段、任务、阻塞、资源、预算、最新事件、预计等待原因和最后心跳。
- 任务详情能查看脱敏日志、输入/输出 artifact、重试历史、错误类别、checkpoint 和下一步。
- pause 是安全边界暂停；cancel 保留结果；强制终止标记可能丢失的任务；每种操作都有明确反馈。
- 终端断开、supervisor 重启、机器重启、模型额度耗尽和 GPU OOM 都显示可恢复路径。
- 长时间后台任务可以配置本地通知或可选 webhook；通知不包含 secret、论文全文或敏感数据。

## P0：成本、资源和安全

- 启动前估算并显示模型 token/费用、GPU 小时、CPU/内存、磁盘和预计墙钟时间；硬配额阻止超支。
- 资源计划由论文、comparison 代码、数据画像和实验协议综合生成；全量多 GPU 训练的资源需求在 handoff 中交付，而不是让探索流程等待它。
- 核心用户价值是跨研究方向复用同一科研探索引擎；验收不能只证明某一个方向可用，还要用第二个不同任务族检查没有方向硬编码。
- 运行中显示已用/剩余预算，接近阈值时暂停新任务或请求用户决定。
- 任务按 GPU 显存、CPU、内存、磁盘和容器权限准入；不能只按 GPU 数量静态并发。
- 凭据只显示存在性和权限范围；支持轮换；失效后不重跑成功任务。
- 原始论文、数据、upstream 仓库和用户代码的保留/删除策略可配置，清理只删除平台拥有的缓存。
- 多用户/共享服务器至少有项目目录隔离、运行锁、artifact 访问边界和审计作者；单用户 MVP 也不能把 secret 写入项目。

## P0：科研结果与交付

- 报告区分原论文结果、本地 comparison 结果、idea 结果、失败实验和未测试场景。
- 每个结论可跳到证据片段、数据 snapshot、切片、代码 commit、环境、run 和日志。
- `handoff` 包含全量实验配置、split manifest、环境锁文件、运行命令、数据准备说明、资源估算和已知风险。
- 报告可导出 Markdown、JSON 和引用/BibTeX；大 artifact 只输出引用和路径，不复制进报告。
- 用户可以标记 idea 有用/无效/已有工作/实验无效，反馈保留为事件并可进入评测集。

## P1：长期维护和扩展

- schema、配置、插件、DSH、模型和实验协议版本可迁移、回滚和解释。
- 依赖下载、容器镜像、embedding 模型和解析缓存支持离线/内部镜像。
- 数据集、论文和 comparison 的增量更新有差异预览，用户知道哪些下游结果会失效。
- 支持项目归档、复制、导出和在另一台 Linux 机器恢复；恢复前校验 artifact hash 和运行环境。
- 当前目录默认绑定一个项目；从任意目录查看/打开历史项目；命令必须显示项目路径并防止跨项目误操作。
- 有独立 gold set、固定实验项目和故障注入回归，不把真实私有项目默认用于平台训练或评测。

## 不应默认做的事情

- 不默认启动全量训练、全量 benchmark、外部数据下载或高成本 embedding 下载。
- 不默认自动排除 comparison、改变主指标、改变测试集用途或发布结果。
- 不把模型自评、相似度分数或单次 quick 提升写成创新已经证明。

## 完成定义

一个产品功能只有在正常路径、用户拒绝路径、配置缺失路径、权限失败路径、重启恢复路径和可观测性路径都可解释时，才可以从本清单打勾。实现、测试、文档和 `PROGRESS.md` 更新必须在同一个模块交付中完成。
