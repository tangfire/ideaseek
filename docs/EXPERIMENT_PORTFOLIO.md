# IdeaSeek 实验组合与泛化验证

单个小数据切片上的提升只能说明“该 idea 在当前切片、协议和随机条件下值得继续”，不能直接说明在大部分实验场景都有效。IdeaSeek 要把一个候选 idea 转化为有层次的实验组合，逐步增加证据强度，并报告仍未知的场景。

## 实验层次

### L0：工程有效性

数据读取、指标、代码、依赖、资源和 checkpoint 可用；极小样本 smoke test 通过。L0 失败不是科学假设失败。

### L1：机制验证

在小规模开发切片上与所有 required comparison 对齐，运行主实验和针对机制的消融/诊断，判断 idea 的预期机制是否产生可观测变化。

### L2：稳定性验证

使用多个随机种子、重复运行、不同子采样或交叉验证，报告均值、方差、置信区间或适用的统计汇总。记录所有尝试，不能只选择最好的一次。

### L3：场景鲁棒性

根据领域适配器和论文证据生成场景矩阵，例如类别不平衡、缺失模态、不同视频长度/帧率、不同图像尺度、不同客户端数量、域偏移、噪声、资源限制或时间窗口。每个场景有预先说明的目的和通过/失败判据。

### L4：跨数据/外部验证

用户提供多个合法数据集时，至少保留一个不参与 idea 选择的确认数据集或域；候选在不同数据分布、主体、域或时间段上验证。用户只有一个数据集时，平台生成补充数据建议并明确外推证据不足，不自动下载或伪造外部验证。

## Idea 晋级

Idea 不以单一总分自动晋级。建议状态：

```text
PROPOSED
  → MECHANISM_SUPPORTED (L1)
  → STABLE_ON_CURRENT_DATA (L2)
  → ROBUST_ACROSS_SCENARIOS (L3)
  → EXTERNAL_VALIDATION_READY (L4)
```

达到 L1 只能称为“机制在当前小规模验证中得到支持”；达到 L2/L3 才能说结果具有一定稳定性/场景鲁棒性；L4 仍不等同于普遍有效。报告必须列出通过、失败、未测试和资源阻塞的场景。

## 场景生成规则

Scenario Planner 从论文实验、失败边界、dataset card、comparison 误差和 idea 机制中提出场景，不允许无目的地穷举。每个场景记录输入变换、预期风险、预算、指标和停止条件；场景之间共享只读数据快照，但各自的结果和配置独立。

## 结果反馈

Result Analyst 不能只看主指标：要区分机制支持、总体提升、稳定性、资源成本和失败模式。某个场景失败时，Idea Agent 可以修订实现、缩小主张、改变假设或创建新 idea；不能把失败场景从报告中删除来提高总体分数。
