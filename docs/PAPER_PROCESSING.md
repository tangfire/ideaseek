# IdeaSeek 论文处理与理解管线

IdeaSeek 不从零编写 PDF 阅读器。论文处理由成熟的 Python/文档工具和 DSH Agent 分层完成：工具负责解析和定位，Agent 负责科学理解，确定性校验器负责证据和结构约束。

## 处理链

```text
PDF/LaTeX/补充材料
  → 文档快照和 hash
  → 文本/章节/参考文献解析
  → 表格/图像/公式/脚注抽取
  → OCR/LaTeX 回退
  → ParsedPaper 统一结构
  → 可引用片段和页码索引
  → Paper Extractor Agent
  → PaperCard + claims + evidence
  → Evidence Checker
  → 主题综合/机制库/研究地图
```

## 不同内容如何处理

### 正文、章节和引用

使用 PDF 文本解析、页码和布局信息，生成带来源 hash、页码、章节和偏移的片段。标题、作者、DOI、参考文献和章节用于去重、检索和论文关系。解析失败的文档进入明确失败状态，不静默丢弃。

### 表格

使用表格提取工具读取表格结构、标题、列名、单元格和页码；保留原始表格 artifact 和结构化 JSON。Agent 可以从表格提取指标、baseline、数据集和消融，但每个数字必须绑定表格/页码证据。复杂跨页或图片表格进入低置信度/OCR/人工复核。

### 图、图注和曲线

提取 figure 图像、图号、图注和邻近正文。优先使用图注和正文解释；如果启用视觉能力，向支持图像输入的 DSH provider 传递受控图像 artifact，让 Agent 解释曲线、架构图和可视化趋势。视觉模型不可用时，平台仍保留图像和图注，但把“只基于图像的结论”标记为未核验/不完整，不把 OCR 文字当成可靠曲线数值。

### 公式、算法框和 LaTeX

优先读取用户提供的 LaTeX 源码、公式文本、算法环境和符号定义；PDF 公式无法可靠解析时保存截图/位置并标记不确定。Agent 可以解释变量、步骤和机制，但主张必须引用公式/算法位置。

### 扫描件和无文本 PDF

渲染页面后使用隔离 OCR venv 进行回退；记录 OCR 引擎、版本、页数限制和识别质量。OCR 输出只能作为解析证据，关键数字和方法细节需要第二次定位核验。

## Agent 的理解方式

Agent 不把整篇论文一次放进上下文。Paper Extractor 按论文/章节/表格任务读取有界片段；Evidence Checker、Synthesis Analyst 和 Idea Agent 通过 FTS/BM25、可选本地 embedding 和 PaperCard 检索相关片段。关键结论回到原文验证，层层摘要不能替代证据。

## 质量状态

每个文档和字段保存：

- parser/OCR/LaTeX/vision 版本；
- 输入文件 hash；
- 页码/章节/图表定位；
- 解析质量和置信度；
- `known`、`inferred`、`uncertain` 或 `unknown` 状态；
- 失败和回退原因。

报告区分“论文作者报告”“平台从原文抽取”“Agent 推断”“本地实验观察”。无法确认的内容使用 `unknown`，不能为了完整 PaperCard 编造。

## 当前能力边界

文本、章节、表格、LaTeX、OCR、证据定位和增量索引可以由成熟工具链和确定性代码完成；图像/曲线的真正语义理解取决于 DSH provider 是否支持视觉输入和当前模型能力。没有视觉能力时，平台仍可利用图注、正文、表格和可解析数据工作，但必须在报告中说明图像证据未完全核验。
