# 科研有效性与完整性规范

IdeaSeek 的小规模实验用于快速淘汰明显无效方向和比较机制，不等于正式论文实验或创新证明。平台必须把“代码能运行”“相对 baseline 有提升”“在更大规模上成立”“具有新颖性”分成不同结论。

IdeaSeek 的 handoff 表示“证据达到配置门槛，值得用户投入全量实验”，不是“全量结果已被平台证明”。报告要区分 `PROMISING`、`HANDOFF_READY` 和用户自行完成的 `USER_FULL_RESULT`；只有用户实际运行并审查全量结果后，才能对最终规模的有效性下结论。

## 实验登记

进入 idea 实验前保存主假设、主指标、方向、数据切分、baseline 集合、消融项、种子数量、预算和停止条件。变更后生成新 Idea/ExperimentSpec 版本，不能覆盖最初登记。

## 数据与选择偏差

- 原始数据只读；训练/验证/确认集的用途固定并记录 manifest。
- 测试/确认集不能用于反复选择 idea、超参数或停止时机。
- 多次尝试、失败实验和无效运行全部保留；报告不能只挑最有利结果。
- 小样本不足以支撑稳定结论时，报告重复运行、方差、置信区间/交叉验证和统计能力限制。
- 有主体、时间、场景或群组相关性时，优先按任务规则做 group/time split，避免泄漏。

## 公平比较

候选与 comparison 尽量共享数据版本、预处理、指标实现、种子策略和计算预算。若方法需要不同资源或预处理，报告差异。官方代码、兼容修复、论文重实现和算法修改分别列出。

## 停止和迭代

自动迭代由预算、最大轮数、无信息增益阈值和明确的支持/否证条件限制。结果分析 Agent 可以建议下一轮，不能因为一个偶然提升无限搜索。科学假设改变时创建新 idea，工程 bug 修复保留同一 idea 的新版本。

## Idea 新颖性与机制门槛

平台不能把新颖性简化为组件名称、论文发布时间或 LLM 自评分。候选至少要有：明确问题矛盾、可解释的介入机制、与最近邻工作的实质差异、可观测预测、能区分竞争解释的实验，以及去掉关键组件后预期失效的消融。仅有“把 A 和 B 放在一起”而没有机制和预测的候选标为草案，不报告为创新 idea。

多 Agent 团队的价值在于产生不同解释并相互挑战，而不是制造一致意见。系统保留独立候选、反方意见、被否决想法和实验失败原因，最终报告说明哪些结论来自证据，哪些只是团队当前的最佳假设。

## 结果标签

建议使用：`supported_on_small_validation`、`inconclusive`、`rejected_by_validation`、`invalid_run`、`baseline_unavailable`、`needs_scale_up`。最终报告说明哪些结果只是当前数据切片上的证据，以及正式大规模实验还需要什么。

## 人工责任

研究者确认研究范围、数据语义、比较集合和最终候选。平台可自动运行预先授权的有限流程，但不把模型自评、自动评分或论文出现频率当作创新和科学正确性的最终裁判。
